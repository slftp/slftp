Shows the in-memory performance timeline of a raced release:
detection time and KB event, first dirlist per site and directory, mkdir
created/started/done with trigger, race creation/assignment/start and results.
Dirlist counters distinguish created tasks, executed tasks and duplicates
discarded by the queue. "Executed" counts entry into slot execution, not FTP
commands or successful listings: a task can retry or exit before sending.
"Parsed" marks the first nonempty listing after its follow-up processing.
First created, started and parsed timestamps can belong to different tasks.
Includes Tuzelj call count and elapsed time, duplicate race drops and failed
race assignment attempts, attributed to the blocking source or destination.
"No slot" includes offline/unavailable slots and transfer limits; "busy" is
split into upload/download cooldown, a destination already marked busy,
assignment lock contention, an active file transfer and a reverse transfer.
Blocked counters count observed attempts, not unique tasks or elapsed time;
queue-level skips before a task assignment is attempted are not counted.
Repeated dirlist tasks count toward totals; timestamps retain the first marker.
Directory detail is always shown when that directory has markers.
"Sent STAT/LIST" counts successfully sent commands, including retries.
"Active" counts outstanding replies; "peak" is the maximum observed at once,
per site (all release directories) and per directory. It excludes CWD and parsing.
"Readd base" is the last configured base delay; "selected" is the observed
minimum/maximum scheduled retry delay, not the measured interval between commands.
No-slot detail separates source/destination roles. The six counts are:
free = no free slot; online = no free online slot found; up = max_up;
dn = max_dn; pre = max_pre_dn; rip = MaxUpPerRip.
"Race allocations avoided" counts duplicates found before creating a task;
these are separate from created tasks and duplicates discarded by AddTask.
Per-directory mkdir timestamps distinguish "usable" (need_mkdir cleared by
listing or mkdir handling) from "processing done" after queue housekeeping.
Site-level first mkdir timestamps can belong to different directories/tasks;
"exec" includes follow-up processing, not just FTP command latency.
"Last FTP issue" records the latest non-success MKD/CWD/PWD reply or command
send/read failure (code 0); text is sanitized and limited to 160 characters.
It may have recovered later (for example MKD 550 File exists), and does not
itself increment the terminal mkdir error counter.
"Complete" includes its first source: "IRC COMPLETE" or "dirlist".
An IRC completion does not require a successful local listing or transfer.
All times are relative to detection. "All tasks done" is the first empty queue,
not necessarily the final completion if tasks are added later.
If the release name exists in more than one section, all matches are shown.
The data is only kept in memory and is gone once the release is removed from
the knowledge base.
Usage: <cmd> rlsname
